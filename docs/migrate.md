# 旧版切换到 v2

v2 不兼容旧 API、agent 协议和数据库结构。不执行数据迁移或历史回填。`scripts/migrate-center-compose.sh` 已关闭，调用它只输出说明，不修改部署。

以下步骤应在部署窗口由运维执行，本次代码实现没有操作生产环境：

1. 记录旧中心/agent 版本、配置和数据位置，确认停机窗口与回退方式。
2. 使用旧版本中心的在线备份功能保存可读备份；停服后一起归档旧数据库及其 WAL/SHM 文件、配置、token 和 agent 状态。不要在仍写入时只复制主数据库文件。
3. 停用旧 agent、旧中心及 `meterly-backup.timer`，保留归档。旧 HTTP 路由不再接收数据。
4. 按 [README](../README.md) 成套安装 v2 中心与 agent。中心设置**新数据库路径**（默认 `meterly-v2.db`），agent 使用新状态目录 `/var/lib/meterly-v2`。原有 `/etc/meterly/agent.json` 若属于旧版，应先人工归档后重新生成。
5. 从新中心生成新的注册码，重新接入主机；旧中心 token 不会自动导入。核对计费网卡、时区、重置日、配额、发现的网站以及 CDN IP 诊断。
6. 从启用时间开始核对网卡、源站日志和代理载荷。之前的时间段应显示尚未采集，不能把旧库的存在视为新数据已回填。
7. 新中心启用内置维护调度，不再安装旧备份 timer。确认首个自动备份成功以及维护目录权限。

回退时停用 v2 服务，用原版本二进制和完整旧配置/旧数据库/旧 agent 状态启动旧系统。不要让旧版本打开新库，也不要将新旧缓冲混用。切换期间两套系统分别保存自己的记录，无法合并为连续历史。

回退 v2 内部的 agent 小版本由独立更新器自动处理；这与跨数据库版本的整体回退是两回事。
